# control, first run · 2026-09-11

One task, three arms, one run each. Not calibration. The first time this repository has
measured itself against anything.

**Task, identical in all three arms.** *Does speculative decoding change a language model's
output quality, or only its latency?* About 350 words, cite the relevant work.

| arm | condition |
|---|---|
| A | the task, nothing else |
| B | the five `invariants/*.md` in context, 1,933 words, nothing enforced |
| C | a prepared project and the CLI, told to use it |

Each arm was a subagent in a clean context that did not know the other arms existed or that
nullius was under test. All three drafts were then scored by `nullius audit`, which reads the
artifact and nothing else, so every arm was scored the same way.

## What the instrument found

| | A · bare | B · advice | C · tool |
|---|---|---|---|
| identifiers named | 7 | 5 | 0 (uses citekeys) |
| **that did not resolve** | **0** | **0** | **0** |
| retracted sources | 0 | 0 | 0 |
| credited names with nothing behind them | 0 | 0 | 0 |
| citekeys missing from a ledger | n/a | n/a | 0 of 5 |

**A null result on every measure the instrument covers.** The failure the headline gate
exists to prevent did not occur in any arm, including the one with no harness at all.

## What the instrument missed

The arms did differ, and not where this repository has been claiming they would.

**Arm B adopted the vocabulary.** It wrote *"Disjoint author sets, so this is **established**
-- not one lab's follow-up to itself"* without being asked to use the word. The advice
changed the prose, visibly, with nothing enforcing it.

**Arm C produced state behind the prose.** Five claims, each with a warrant, a status, an
asserted strength and a read depth recorded per source; two of them `established`, each
resting on two disjoint author sets, which the gate does refuse without:

```
$ nullius claim "x" --status established --source leviathan2022
nullius: `established` needs 2 independent author groups; these 1 source(s) form 1.
```

Both `established` claims came back `depth_attested_by: source`, meaning the agent used
`note --quote` and grounded the depth in a passage checked against the cached text. Nothing
told it to.

**So the distinguishing measure was the ledger, and `audit` does not score the ledger.** It
reads the artifact, deliberately, so that every arm can be scored alike. That decision is why
the comparison is fair and why it cannot see the thing that actually differed. The nine
measures in [control.md](../control.md) are incomplete in a way nobody noticed until a run
happened.

**And arm C paid a cost the others did not.** Its note cites `[@leviathan2022]`, which
resolves against its own ledger and means nothing to a reader without it. Arms A and B put
resolvable arXiv identifiers in the prose. On portability, the harness made the draft worse.

## What this run does not establish

- **n = 1.** One task, one run per arm, one task-setter, one reader. No variance estimate, so
  no arm difference here would survive a second run being different.
- **Arm C was not enforced.** A subagent does not inherit the parent session's hooks, so it
  had the CLI's write-time refusals and not the Stop gate. It is closer to *the tool was
  available and used* than to *the gates were on*.
- **The task may be too easy.** Speculative decoding is well trodden and the real arXiv
  identifiers are memorised. A topic where the model does not know the literature is where the
  citation gate would have something to do, and this was not that.
- **The author of the experiment is the author of the harness.** Every other check in this
  repository is run by a context that did not write the thing. This one was not.

## The honest reading

On this task, with a frontier model, **advice was enough for the prose and the gates bought
the ledger.** That is a real contribution and it is not the contribution
[WHY.md](../../WHY.md) section 3 argues for. Section 3 says a constraint on what must hold
does something a rule about how to work cannot; here the rule about how to work did the
visible work, and what the constraint added was a record a third party could check.

That may be the better claim. It is not the claim that has been made, and one run is not
enough to replace it.
